# Windows CPU public-weights experiment

This is a standalone experiment. All care records, identities and measurements in `cases.json` are fictional. It is not connected to the care application, Google Drive, its installed data or provider accounts. No credentials or original business records are included.

It evaluates pinned public GGUF weights with a pinned llama.cpp Windows CPU runtime. The initial baseline uses Qwen3-4B-Instruct-2507. `profiles.json` adds TinySwallow 1.5B, Qwen3.5 4B, Qwen3 8B, Japanese Swallow 8B, DeepSeek-R1-0528-Qwen3-8B and Qwen3 14B, plus separately labelled Qwen3.5 reasoning, compact-prompt and conservative-decoding follow-ups. Model and runtime checksums are verified before use. No API key or paid runner is used. The standard public `windows-latest` runner is used, with no model cache or model artifact. Only small results are retained for one day.

The existing private application's pure prompt builders were used locally to export the task instructions and synthetic cases. Its report contract is preserved: family daily prose; CM monthly overview, fixed utilization/bathing table, dated exceptions, per-goal monthly course, wishes, support plan and CM requests. Goal-period attainment is a separate document. Only prompts and fabricated fixtures are published here, not the private application code or data.

For the initial setup/recovery baseline, run `node experiments/local-llm/selftest.cjs`, then `node experiments/local-llm/run.cjs` on Windows x64 with Node 24. For a model comparison, set `EXPERIMENT_PROFILE` to an ID in `profiles.json`, then run `node experiments/local-llm/compare.cjs`. `EXPERIMENT_CASES` can select known case IDs. The runtime download is about 25 MB. The baseline weights are 2,497,281,120 bytes; comparative weights range from about 1.1 to 9.0 GB. Allow additional runtime, temporary files, context memory and OS headroom. Available-memory guards are experimental and do not certify operation on ordinary 8 GB or 16 GB laptops.

The installer checks free disk and memory, locks concurrent installs, resumes supported downloads, verifies SHA-256 and preserves a verified model across the experiment's application-version change. The server binds to loopback only, has a temporary random API key, runs CPU only, disables prompt caching, uses one slot and receives a new conversation for every case. No session files are saved. This does not claim physical memory erasure or privacy certification.

`selftest.json` separates injected errors from real runtime behavior. `report.json` records environment, install/start/response timings, Windows process-memory measurements, validation and restart. `*.raw.json` retain the unmodified model responses. `samples.html` is a readable review of those responses using the accepted information hierarchy, not the product's actual print renderer. The sample's fixed numerical table is deterministic, not generated by the LLM.

Success of JSON/schema checks is **not** semantic acceptance. Review the raw output for invented facts, subject/date confusion, stale follow-up, repetition and missing content. The baseline covers eight fictional cases. The main comparison screens four common cases, and configuration follow-ups repeat three known cases. A promising configuration would still need independent scenarios and repeat sampling. This is not a clinical/statistical assessment or a clean-laptop acceptance test. A failed case stays in the evidence; the workflow does not silently rewrite it. Follow-ups are distinct runs and retain the earlier failures.

The main comparison uses exported original product instructions and the same source records/output contract. `compact-prompt.cjs` changes system instructions only, retaining the original source JSON and schema. Conservative decoding additionally sets temperature and presence penalty to zero. Different families, tokenizers, quantizations, native sampling and CPU hosts mean this is not an isolated experiment on parameter count. The 14B profile disables weight repacking to fit the runner's RAM; timing is not directly comparable.

Semantic review is separate from two automated checks: the public screening validator, and a local invocation of the unchanged private application's validator. The assistant compared the outputs with fictional sources; no human clinician acceptance is claimed. Numeric wording supported by the records can still be rejected by an application rule; such a compatibility rejection is not automatically a hallucination. Outputs remain unedited in all evidence.

The completed screening summary is in `experiment-results.json`. No tested configuration was accepted unchanged for the full workflow, and no minimum parameter count was established. This does not rule out narrower tasks, different data organization or further model-specific optimization. Automatic push-triggered experiments are disabled after collection. No production integration or installer change was made.

The DeepSeek job's final viewer failed on malformed output after all four model responses had completed and been saved. The viewer now shows rejected output as raw JSON. This rendering repair does not make that output pass its format or semantic checks.

Quantization: [Unsloth GGUF](https://huggingface.co/unsloth/Qwen3-4B-Instruct-2507-GGUF), pinned in `manifest.json`. Other model cards, quantizers, revisions, hashes and license notes are in `profiles.json`. Dependencies retain their respective licenses; a production distribution needs its own license/package review.
